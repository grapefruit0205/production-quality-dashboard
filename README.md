# 생산·품질 대시보드 (구글시트 + Apps Script)

생산일보 **5,475행**(12개월 × 5라인 × 3교대)에서 집계 5탭 · KPI 카드 6장 · 차트 6개 대시보드 · 경영진 리포트 PDF · 엑셀(.xlsx) 사본을 자동으로 만드는 예제입니다.

> ⚠️ **데이터는 전부 합성(가상)입니다.** 실제 회사 자료·라인명·인명을 쓰지 않았습니다. 예제 회사는 `(주)가상케미칼 생산1팀` 입니다.
> 실행 환경: 구글 계정(무료) + Apps Script. 별도 서버·유료 라이선스·부가기능 없음.

같은 계열의 앞선 예제: ① [현장 점검표 자동 집계·주간보고](https://github.com/grapefruit0205/plant-inspection-automation) · ② [실무 서류 자동 생성 세트](https://github.com/grapefruit0205/office-docs-automation)
— 세 프로젝트는 같은 도구 함수(재시도·캐시·3단계 내보내기·자가 진단)와 같은 문서 구조를 씁니다.

---

## 1. 무엇을 하는가

현장에서 매달 손으로 만드는 **생산·품질 월간 보고**(집계표 → 차트 → 보고서 1장)를 데이터에서 자동으로 만들어 냅니다.

| 구분 | 내용 |
|---|---|
| 입력 | 생산일보 5,475행(일자 × 라인 5 × 교대조 A/B/C) · 라인마스터 5행 · 월별 목표 12행 |
| ① | 집계 5탭 — 월별 / 라인별 / 불량유형별(파레토) / 교대조별 / 정지사유별 (`SUMIFS`·`COUNTIFS` 수식) |
| ② | 대시보드 — KPI 카드 6장(전월 대비 포함) + **자동 생성 종합 코멘트** + 차트 6개 |
| ③ | 리포트 — 경영진 보고용 1장(핵심 지표·월별·라인별·코멘트·조치 제안·결재란) → **PDF** |
| ④ | 엑셀(.xlsx) 내보내기 — 집계 탭을 값으로 굳힌 사본(엑셀에서 그대로 열림) |
| ⑤ | 월간 트리거 — 매월 1일 아침 대시보드 갱신 + 리포트 PDF 자동 실행 · 자동/수작업 소요 시간 로그 |

**핵심**: 집계 수식은 엑셀에서도 그대로 계산되는 것만 씁니다.
`SUMIFS` `COUNTIFS` `IFERROR` `IF` `TEXT` `XLOOKUP`(또는 `INDEX/MATCH`) — `QUERY` `FILTER` `ARRAYFORMULA` 는 엑셀에 없으므로 쓰지 않았습니다.
`ARRAYFORMULA` 대신 행마다 수식을 넣고(5,475행 × 3열 = 16,425개), 범위는 전체 열이 아니라 **실제 데이터 범위(`$2:$5476`)** 로 잡습니다.

합성 데이터에는 대시보드가 짚어낼 **이야기**를 심어 두었습니다: 겨울 감산·주말 감산, 야간(C조) 불량률 1.3배, L4 라인의 만성적 목표 초과, 그리고 **2026-05 L3 라인의 이물혼입 급증**(연평균의 약 3배). 종합 코멘트가 이것을 자동으로 문장으로 씁니다.

## 2. 시트 구성 (13탭)

| 탭 | 내용 | 채우는 방법 |
|---|---|---|
| `안내` | 사용 순서·구성 설명 | 설치 시 코드가 작성 |
| `대시보드` | KPI 카드 6 · 종합 코멘트 · 차트 6 | `대시보드갱신` 이 통째로 다시 그림 |
| `리포트` | 경영진 보고용 1장(값으로 굳힘) | `리포트_PDF` 가 작성 |
| `집계_월별` | 월 × 계획·생산·달성률·목표·불량수·불량률·목표대비·가동률·정지시간·판정 | `SUMIFS` 수식 12행 |
| `집계_라인별` | 라인 × 생산·불량률·목표·판정·가동률 (목표 초과는 빨강) | `SUMIFS` 수식 5행 + 조건부 서식 |
| `집계_불량유형별` | 불량유형별 불량수·비율·**누적%(파레토)** · 발생건수 | 불량수 많은 순으로 정렬해 수식 6행 |
| `집계_교대조별` | A/B/C 교대조별 생산·불량률·가동률 | `SUMIFS` 수식 3행 |
| `집계_정지사유별` | 정지사유별 건수·시간·비율 + 라인별 시간(누적 막대용) | `SUMIFS`/`COUNTIFS` 수식 7행 |
| `생산일보` | 1행 = 일자 × 라인 × 교대조 (5,475행). 월·라인명·불량률(%)은 수식 | 데이터 |
| `목표` | 월별 목표 생산량·목표 불량률(%) | 데이터(샘플이 채움, 수정 가능) |
| `라인마스터` | 라인 5개 기준 정보 | 데이터 |
| `설정` | 회사명·기간·조회함수·한 번에 처리할 행 수·출력 폴더 등 16개 | 설치 시 기본값 |
| `측정로그` | 자동/수작업 소요 시간 비교 | 실행 시 자동 |

- 단위: 수량은 **포(25kg)**, 시간은 h, 비율은 전부 **% 숫자**(1.23 = 1.23%).
- 정의: 달성률 = 생산 ÷ 계획 × 100, 불량률 = 불량수 ÷ 생산수량 × 100, 가동률 = 가동시간 ÷ (가동 + 정지) × 100. 시트 수식과 스크립트(코멘트·리포트)가 **같은 정의**를 씁니다.
- `생산일보` 의 `월`·`라인명`·`불량률(%)` 은 값이 아니라 수식입니다. 라인마스터를 고치면 5,475행이 따라 바뀝니다. 구버전 엑셀이면 `설정` 의 `조회함수` 를 `INDEXMATCH` 로 바꾸고 갱신하세요.

|---|---|---|---|---|---|
| 12개월 합계 | 목표 초과 시 빨강 | 기준(95%) 미달 시 빨강 | 가동 ÷ (가동+정지) | 12개월 합계 | 파레토 1위 · 비율 |

**종합 코멘트** (스크립트가 실행 시점에 문장으로 생성 — 예시)

> 2026-09 생산 499,238포(전월 대비 +5.8%), 불량률 1.14%(목표 1.20% 달성), 전월 대비 +0.01%p, 가동률 95.0%. 기간 누적(2025-10~2026-09) 생산 5,746,804포 · 목표 달성률 98.3% · 평균 불량률 1.17% · 평균 가동률 95.1% · 총 정지시간 2,166.3h. 목표 불량률(1.20%)을 넘긴 라인: L4 1.67%, L3 1.25%. 최다 불량유형은 치수불량(17,597포, 전체의 26.1%), 최다 정지사유는 설비고장(684.6h, 481건). 특이사항: 2026-05 L3 불량률 3.79%(라인 연평균의 3.0배) — 그 달 최다 불량유형은 이물혼입. 원인 조사와 재발 방지 조치 확인이 필요합니다.

## 4. 실행 순서

| 순서 | 실행 | 기대 결과 |
|---|---|---|
| 1 | `설치_전체` | 탭 13개·설정 16개·드라이브 폴더·대시보드 틀. **두 번 돌려도 데이터가 지워지지 않습니다** |
| 2 | `설치_샘플데이터` | 생산일보 5,475행 + 목표 12행 + 라인 5행 → 수식 16,425개 → 집계 5탭 → 대시보드(차트 6) |
| 3 | `설치_확인` | 12항목 ○/× 자가 진단 → `=== 결과: 정상 12 / 문제 0 ===` |
| 4 | 메뉴 **[대시보드] → 리포트 PDF 내보내기** | 드라이브 `생산품질대시보드_포트폴리오/출력/생산품질_리포트_2026-09.pdf` |
| 5 | 메뉴 **엑셀(.xlsx) 내보내기** | `출력/생산품질_대시보드_2026-09.xlsx` (엑셀에서 열림) |
| 6 | 메뉴 **월간 트리거 설치** (선택) | 매월 1일 07시 `대시보드갱신` + `리포트_PDF` |

행을 추가했거나 목표를 바꿨으면 메뉴 **대시보드 갱신** 을 실행합니다 — 수식 범위(`$2:$N`)를 다시 잡고 집계·카드·차트를 다시 그립니다.
시트 메뉴 `[대시보드]` 는 설치 후 시트를 새로 열면 생깁니다. 무엇이 안 되면 편집기에서 `설치_확인` 을 먼저 돌립니다.

무료 계정의 **1회 실행 6분 제한** 대비: 샘플 데이터는 2,000행씩 나눠 쓰고, 시간이 넘으면 진행 위치를 저장했다가 **다시 실행하면 이어서** 씁니다(`설정` 의 `한번에처리행`·`시간제한초`).

## 5. 검증

구글에 올리기 전에 **로컬 스텁 하네스**(`dev/stub_test.js`, Node.js)로 전 구간을 돌립니다. Apps Script 런타임(SpreadsheetApp·DriveApp·Charts·ScriptApp·MailApp)을 흉내 내고, 실제 API 에서 겪은 제약을 일부러 재현해 회귀를 막습니다.

```
node dev/stub_test.js            # 파일 3개를 최악의 순서(설치.js → 대시보드.js → Code.js)로 로드
ONEFILE=1 node dev/stub_test.js  # 붙여넣기용 합본(설치_한번에.js)만 로드
→ === 단언 80개 중 통과 80 / 실패 0 ===
```

| 검증 항목 | 내용 |
|---|---|
| 전체 흐름 | 설치_전체 → 설치_샘플데이터 → 설치_전체(재실행) → 대시보드갱신 → 리포트_PDF → 엑셀내보내기 → 트리거 → 설치_확인 12/0 |
| 수식 규칙 | 집계·대시보드 수식 320개에 `QUERY`/`FILTER`/`ARRAYFORMULA` 0개, 전체 열(`$A:$A`) 참조 0개, 범위 `$2:$5476` |
| 데이터 이야기 | 전체 불량률 0.7~1.8% · L4 목표 초과 · C조 > A조 · 2026-05 L3 급증(연평균 3.0배) · 코멘트가 이것을 짚음 |
| 주입 실패 1 | `Service Spreadsheets timed out` 1회 → 재시도로 통과 · 3회 연속 실패 → 오류를 삼키지 않고 그대로 올림 |
| 주입 실패 2 | 측정로그에 빈 줄 2·중복 1 주입 → `설치_전체` 가 자동 정리 |
| 주입 실패 3 | 필터가 있는 시트에 `createFilter` → 하네스가 거부(실제 API 재현) → 코드는 제거 후 재생성으로 `[건너뜀]` 없음 |
| 주입 실패 4 | `getAs(xlsx)` 거부(실제 계정에서 났던 오류) → 다운로드 URL 경로로 자동 전환 |
| 6분 제한 | 시간제한 0.001초 → 2,000행에서 `[중단]` → 재실행 시 `[이어서]` 로 5,475행 완성 |
| 내부 함수 보호 | `_차트만들기()` 등 8개를 인수 없이 실행 → "메뉴 [대시보드] → … 으로 실행하세요" 안내 예외 |
| 멱등성 | 재설치 후 행 수·설정 값 유지, 차트 6개(겹치지 않음), 트리거 재설치 시 1개 유지 |
| 로드 순서 | `SH` 를 정의하는 `Code.js` 를 마지막에 로드해도 오류 없음(최상위 교차 참조 없음) |

하네스가 잡지 못하는 것(실제 화면 배치·차트 렌더링·PDF 모양)은 구글에서 직접 확인해야 합니다 → `docs/prompt-log.md` 5절.

## 7. 코드 구조

| 파일 | 역할 |
|---|---|
| `Code.js` | 공통 도구(로그·재시도·캐시·설정) · 생산일보 수식/서식 · 집계 5탭 수식 · 3단계 내보내기 · 측정로그 정리 |
| `대시보드.js` | KPI 카드 · 차트 6 · 자동 코멘트 · 대시보드갱신 · 리포트 작성/PDF · 엑셀 내보내기 · 메일 알림(선택) · 월간 트리거 |
| `설치.js` | 탭·설정·폴더 설치 · 합성 데이터 생성(시드 고정, 분할·이어쓰기) · 자가 진단 12항목 · 메뉴 · 수작업 측정 |
| `설치_한번에.js` | 위 3개를 합친 파일 — 편집기에 붙여넣기용 (`dev/build_일괄.sh` 로 생성) |
| `dev/stub_test.js` · `dev/regression_test_tail.js` | 로컬 검증 하네스(개발용, Apps Script 에 올리지 않음) |
| `appsscript.json` | 시간대 Asia/Seoul · V8 · 권한 범위 |

설계 원칙(②에서 실제로 겪은 오류에서 나온 것):
- 무거운 호출(큰 범위 `setValues`/`setFormulas`·행 삭제·조건부 서식·필터·차트 삽입)은 `_재시도()` 로 감싸 **1.5초·3초 쉬었다 최대 3회** 재시도. 그래도 안 되면 오류를 그대로 올립니다.
- 설정·생산일보·라인·목표는 한 실행 안에서 **한 번만 읽는 캐시**(`_설정캐시`·`_생산값()`), 값을 쓰면 무효화.
- 드롭다운은 `requireValueInList`(값 목록) — 내보낸 xlsx 는 다른 파일이라 범위 참조가 죽습니다.
- 조건부 서식은 **같은 시트만** 참조(구글시트·엑셀 모두 다른 시트 참조 불가) → 대시보드에 기준값 행을 둡니다.
- 월 키(`2025-10`)는 텍스트 서식(`@`)을 먼저 주고 씁니다 — 그냥 쓰면 시트가 날짜로 바꿔 `SUMIFS` 가 어긋납니다(`설치_확인` 이 검사).
- 다른 파일의 최상위 값은 **함수 안에서만** 참조(Apps Script 는 파일 로드 순서를 보장하지 않음).

## 8. 재현 방법

### 방법 A — 붙여넣기 (가장 빠름)
1. 구글시트를 새로 만들고 이름을 `생산품질_대시보드` 로 변경
2. **확장 프로그램 → Apps Script** → `Code.gs` 내용을 지우고 `설치_한번에.js` 전체를 붙여넣기
3. 프로젝트 설정(⚙) → "`appsscript.json` 매니페스트 파일 표시" 체크 → `appsscript.json` 내용으로 교체
4. 저장(Ctrl+S) → 함수 `설치_전체` 실행 → 권한 허용(본인 스크립트이므로 **고급 → 프로젝트로 이동**)
5. `설치_샘플데이터` → `설치_확인` → 시트로 돌아가 F5 → 메뉴 `[대시보드]` 확인

```bash
npm install -g @google/clasp
```

```bash

```

```bash
clasp create --type sheets --title "생산품질_대시보드" --rootDir .
```

> `clasp` 는 `설치_한번에.js` 를 올리지 않습니다(`.claspignore`). 같은 함수가 두 번 선언되면 실행이 깨지기 때문입니다.

## 9. 한계와 다음 단계

- **차트는 .xlsx 로 내보내면 빠집니다.** 구글 차트는 엑셀 차트로 변환되지 않습니다. 그래서 집계 5탭(값으로 굳힘)이 통합문서의 본체이고, 차트가 필요하면 PDF(리포트)나 구글시트 원본을 봅니다.
- 리포트의 숫자는 **실행 시점의 값**(스냅샷)이고 대시보드 카드는 수식(실시간)입니다. 둘의 정의는 같지만, 데이터를 바꾼 뒤에는 `리포트_PDF` 를 다시 실행해야 리포트가 따라옵니다.
- 엑셀·PDF 변환은 `getAs` 가 계정 상태에 따라 막히는 경우가 있어 **다운로드 URL 경로까지 자동으로 시도**합니다(`_내보내기()`). 둘 다 안 되면 구글시트 사본을 `출력` 폴더에 남기고 로그에 `[대체]` 로 남깁니다.
- `대시보드갱신` 은 생산일보 수식 16,425개를 매번 다시 씁니다(범위를 다시 잡기 위해). 실제 환경에서 수십 초가 걸리며, 행이 수만 행이면 수식 열을 값으로 바꾸는 편이 낫습니다.
- Pareto 의 정렬 순서는 갱신 시점에 스크립트가 정합니다(수식만으로 안정적인 정렬이 어려움). 데이터를 바꾸면 `대시보드갱신` 으로 다시 정렬됩니다.
- 메일 알림은 `설정` 의 `메일알림` 이 비어 있으면 `[건너뜀]` 으로 넘어갑니다(기본값). 피벗·Sheets API 고급 서비스는 쓰지 않습니다.
- 실제 업무에 적용할 때는 ① 라인마스터·목표를 회사 기준으로 바꾸고 ② 생산일보를 폼/설비 로그에서 자동 입력받게 하고 ③ 개인정보가 들어가는 열(작업자)을 뺄지 정하는 순서를 권합니다.
